Installation

desc 3.0 runs on PyTorch and requires Python 3.14 or newer. You can check your Python version with:

python3 --version

If you need a newer Python, uv can install one for you with uv python install 3.14.

  • uv (recommended)
    Add desc to a uv project, or install it into the current environment:
# add desc to your uv project
uv add desc
# or install it into the current environment
uv pip install desc
# CPU-only machines can avoid downloading the CUDA build of PyTorch
uv pip install desc --torch-backend cpu
  • pip
    pip install desc works as well. On Linux, pip installs the CUDA build of PyTorch from PyPI.
python3 -m pip install desc
  • Github
    To work on desc itself, clone the repository from Github and let uv create the environment. Pick a PyTorch build with an extra: cpu, cu126 or cu130. Without an extra, PyTorch comes from PyPI.
git clone https://github.com/eleozzr/desc
cd desc
uv sync --extra cpu
uv run pytest

Older versions: desc 2.0.3 (TensorFlow 1) and desc 2.1.1 (TensorFlow 2) remain on PyPI for TensorFlow users, for example pip install desc==2.1.1. They need the Python versions those TensorFlow releases support.

Please check desc Tutorial for more details.


What changed in 3.0

  • DESC runs on PyTorch instead of TensorFlow/Keras. The architecture, initializers, SGD schedules, losses and early stopping follow the 2.x implementation. Calls such as desc.train(adata, ...) work unchanged. Results are not bit-identical to 2.x because the random number generators differ.
  • Files in save_dir are PyTorch files: ae_weights.pt, encoder_weights.pt, autoencoder_model.pt and encoder_model.pt. Reload a saved model with desc.models.network.load_model. With use_ae_weights=True, desc still loads an ae_weights.h5 written by desc 2.x if no ae_weights.pt exists.
  • The Louvain initialization uses igraph with the given louvain_resolution. The louvain package used before cannot be installed on current Python versions.
  • Bug fixes: alpha now reaches the t-distribution kernel; sparse and pandas.DataFrame input to desc.train works; is_stacked=False runs 50 epochs per learning-rate step; a single detected cluster raises a ValueError instead of exiting Python; training no longer changes CUDA_VISIBLE_DEVICES or the matplotlib backend.


Run a quick desc test

Now, let us run a quick test to see if the desc is ready.

Firstly, enter Python’s interpreter from your console:

$ python

Then, in a Python interpeter session, type

>>> import desc
>>> desc.run_desc_test()

The run_desc_test() function enables you to perform a quick desc analysis on a small pre-processed data. It takes about a minute on a CPU. If you see something like:

“The desc has been trained successfully!!!!!!”
…
“The run time for all resolution is: xxx.xxxx”.

Then you are ready to go.


Using a GPU

Pass both use_GPU=True and a GPU_id to train on that CUDA device. On a Mac with Apple silicon, desc uses the MPS backend instead. Without a GPU, desc prints a warning and uses the CPU.

adata = desc.train(adata, use_GPU=True, GPU_id=0)

Note: use_GPU=True without a GPU_id still trains on the CPU, as in desc 2.x.


Troubleshooting

  • If the installer reports that no version of desc 3.0 matches your environment, your Python is older than 3.14. Install a newer Python, for example with uv python install 3.14, or use desc 2.1.1.
  • If PyTorch downloads several gigabytes on a machine without an NVIDIA GPU, install the CPU build instead with uv pip install desc --torch-backend cpu.
  • If use_GPU=True prints a CPU warning on a machine with an NVIDIA GPU, check that python -c "import torch; print(torch.cuda.is_available())" prints True. If it prints False, you have the CPU build of PyTorch or a driver that is too old for it.
  • desc 3.0 depends on igraph, which ships prebuilt wheels for Linux, macOS and Windows. You no longer need to compile it or install pycairo or pydot.
