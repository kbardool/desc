❯ does the new version support GPUs?                                            

● Yes, in code, but it hasn't been run on a GPU. This machine has none, so every
  test and benchmark so far ran on CPU.

  How to use it. It works the same way as 2.x: pass both use_GPU=True and a
  GPU_id.

  adata = desc.train(adata, ..., use_GPU=True, GPU_id=0)

  - NVIDIA: training runs on cuda:<GPU_id>. If you pass something like "0,1", it
    uses the first GPU. There's no multi-GPU training.
  - Apple Silicon: if CUDA isn't available, it uses the Mac's GPU through
    PyTorch's MPS backend.
  - No GPU: it prints a warning and falls back to CPU.
  - Gotcha: use_GPU=True with no GPU_id still runs on CPU. That matches 2.x and
    its docstring, but it's easy to trip over.
  - Lower level: DescModel and SAE take a device argument directly
    (device="cuda:0").

  What I've checked without a GPU. I read through the code paths for device
  mix-ups. The model and the training data are moved to the chosen device,
  results come back to the CPU, and loading saved weights maps them onto the
  model's device. The Louvain step and scanpy always run on CPU, as before.

  What's unverified:
  - It runs at all: no test has executed the CUDA or MPS code paths.
  - Speed: DESC's networks are tiny (about 7,500 parameters on PBMC) and train
    in batches of 256. GPU launch overhead may cancel out any gain, so a GPU may
    not be faster than the 20–35 s CPU runs I measured.
  - Reproducibility: I didn't turn on PyTorch's deterministic mode, so repeated
    GPU runs with the same seed may differ slightly. CPU runs are repeatable.

  Installation:
  - pip install desc or uv add desc on Linux pulls the CUDA build of PyTorch
    from PyPI by default.
  - On macOS the default build includes MPS.
  - In the repo, uv sync --extra cu126 or --extra cu130 picks a specific CUDA
    build.

  On a GPU machine, the existing tests plus one GPU run would settle it:

  uv sync --extra cu130
  uv run pytest
  uv run python -c "import desc; a=desc.datasets.pbmc_processed(); desc.train(a,
  dims=[100,64,16], louvain_resolution=0.8, use_GPU=True, GPU_id=0)"

  The run should print no fallback warning. I can also add a GPU test that skips
  automatically when no GPU is present.
